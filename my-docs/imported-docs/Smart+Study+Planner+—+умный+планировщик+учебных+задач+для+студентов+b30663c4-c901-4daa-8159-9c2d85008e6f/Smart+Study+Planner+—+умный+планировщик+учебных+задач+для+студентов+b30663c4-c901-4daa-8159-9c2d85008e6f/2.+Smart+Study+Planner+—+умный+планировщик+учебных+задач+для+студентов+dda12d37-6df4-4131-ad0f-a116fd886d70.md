# ЧАСТЬ 2. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ (MVP)

## UC-01 Регистрация

ID: UC-01
Акторы: Студент
Предусловия: отсутствуют

Основной поток:

1. Пользователь вводит email и пароль.

2. Система валидирует данные.

3. Аккаунт создаётся.

Постусловия: аккаунт создан.

## UC-02 Создание задачи

ID: UC-02
Акторы: Студент
Предусловия: пользователь авторизован

Основной поток:

1. Нажать «Добавить задачу».

2. Ввести параметры.

3. Сохранить.

Постусловия: задача сохранена.

## UC-03 Генерация плана

ID: UC-03
Акторы: Студент
Предусловия: существуют задачи

Основной поток:

1. Нажать «Сформировать план».

2. Система анализирует дедлайны и сложность.

3. Формирует недельный план.

4. Отображает результат.

Постусловия: план сохранён.

# НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

## NFR-01 Производительность

Время отклика ≤ 1 сек для 95% запросов.
Приоритет: Must Have
Обоснование: влияет на удержание.

## NFR-02 Доступность

SLA ≥ 99%.
Приоритет: Must Have

## NFR-03 Безопасность

Соответствие 152-ФЗ, TLS 1.2+.
Приоритет: Must Have

## NFR-04 Масштабируемость

Поддержка 50 000 одновременных пользователей.
Приоритет: Should Have

## NFR-05 Надёжность

Ежедневное резервное копирование.
Приоритет: Should Have

## Обоснование непокрытых категорий

Не покрыты:

- Локализация (MVP запускается только в РФ)

- Портируемость (только веб-версия)

- Совместимость с LMS (вне MVP)

Риски низкие. Планируется расширение в версии 2–3.
