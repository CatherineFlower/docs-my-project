### **1. Функциональность для замены на платформу**

В системе **Smart Study Planner** можно заменить функциональность: получение учебных задач и дедлайнов

Сейчас задачи пользователь вводит вручную, но в реальности они уже существуют во внешних системах (LMS вуза).

### Что я дополняю:

- создание задач

- дедлайны

- часть календарных событий

### **2. Выбранное решение**

Используется **LMS API (например, Moodle или Canvas)**

#### Как используется:

1. Пользователь подключает LMS (OAuth / токен)

2. Приложение получает:

    - список курсов

    - задания (assignments)

    - дедлайны

1. Данные преобразуются в `Task` и `Event`

2. Используются при генерации плана

#### Что это даёт:

- убирается ручной ввод

- данные всегда актуальны

- сокращается объём разработки

### **3. Стратегия платформизации**

Smart Study Planner можно продавать как **надстройку над LMS**.

#### Кому продавать:

- университеты

- онлайн-школы

- EdTech-платформы

- корпоративные обучающие центры

#### Ценность:

- не заменяет LMS

- дополняет её → превращает задания в готовый план

### **4. Модель бизнеса**

**B2B2C**

```Plain Text
Платформа → организация (вуз) → студенты
```

Почему:

- платит организация

- пользуются студенты

- масштабируемо

### **5. Монетизация**

**Подписка**

Варианты:

- фиксированная стоимость для организации

- оплата за активного пользователя

Почему так:

- предсказуемая модель

- легко масштабируется

- стандарт для SaaS

### **6. Почему проект платформизуем**

Проект можно сделать платформой, потому что:

- работает с универсальными сущностями (задачи, дедлайны, календарь)

- не зависит от конкретного вуза

- легко интегрируется с разными LMS

- основная ценность - **алгоритм планирования**, а не хранение данных
