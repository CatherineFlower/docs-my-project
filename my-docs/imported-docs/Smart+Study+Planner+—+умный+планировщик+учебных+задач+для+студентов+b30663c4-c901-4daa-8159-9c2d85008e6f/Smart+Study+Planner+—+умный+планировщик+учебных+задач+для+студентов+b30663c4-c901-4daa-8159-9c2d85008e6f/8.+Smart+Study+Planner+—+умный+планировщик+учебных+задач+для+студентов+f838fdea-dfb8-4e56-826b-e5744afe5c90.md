# Интеграции II: проектируем асинхронное взаимодействие

## **1. Выбранное асинхронное взаимодействие**

В системе в качестве асинхронного взаимодействия подходит **генерация недельного плана**.

Сценарий:

1. Пользователь на экране `/generate-plan` выбирает задачи и события.

2. Нажимает кнопку **«Сгенерировать»**.

3. Сервер принимает запрос и запускает процесс генерации плана.

4. Пока план формируется, клиент получает обновления статуса.

5. После завершения пользователь открывает готовый недельный план.

Так как генерация плана может занимать заметное время (системе нужно обработать список задач, учесть события календаря и распределить нагрузку по дням), то я ее как раз и выбрала как асинхронное взаимодействие.

## **2. Выбор технологии**

Я выбрала технологию **WebSocket**.

### **Почему WebSocket**

- в системе есть мобильный клиент;

- нужно показывать пользователю изменение статуса в реальном времени;

- сообщения небольшие: статус, прогресс, ошибка, готовность плана;

- не нужно постоянно опрашивать сервер через polling.

### **Почему не RabbitMQ / Kafka / NATS**

- эти технологии больше подходят для обмена между сервисами;

- в данной ситуации нужно уведомлять именно клиентское приложение;

- для пользовательского интерфейса WebSocket проще и понятнее.

### **Почему не gRPC streams**

- для мобильного приложения и push-обновлений статуса WebSocket - проще;

- JSON-формат удобнее для такого сценария.

## **3. Логика взаимодействия**

### **3.1 Запуск генерации**

**Endpoint:** `POST /plans/generate`

Назначение: принять запрос на генерацию плана.

Клиент отправляет:

- `taskIds`

- `eventIds`

Сервер возвращает:

- `202 Accepted`

- `generationId`

После этого генерация продолжается уже отдельно от HTTP-запроса.

### **3.2 Получение статусов**

**Channel:** `/ws/plans/generation-status`

Назначение: отправка статусов генерации плана на клиент.

Возможные статусы:

- `queued`

- `processing`

- `completed`

- `failed`

## **4. Атрибутивный состав сообщений**

Каждое сообщение содержит:

- `eventType` - тип события;

- `generationId` - идентификатор генерации;

- `userId` - идентификатор пользователя;

- `status` - текущий статус;

- `timestamp` - время события.

Дополнительно:

- `progress` - процент выполнения;

- `planId` - идентификатор готового плана;

- `errorCode` - код ошибки;

- `message` - текстовое описание.

## **5. AsyncAPI**

```YAML
asyncapi: 3.0.0
info:
  title: Smart Study Planner Async API
  version: 1.0.0
  description: Асинхронное взаимодействие для генерации недельного плана

servers:
  production:
    host: api.smartplanner.com
    protocol: wss
    description: WebSocket сервер

channels:
  planGenerationStatus:
    address: /ws/plans/generation-status
    messages:
      PlanGenerationStatusMessage:
        $ref: '#/components/messages/PlanGenerationStatusMessage'

operations:
  receivePlanGenerationStatus:
    action: receive
    channel:
      $ref: '#/channels/planGenerationStatus'
    summary: Получение статуса генерации плана
    messages:
      - $ref: '#/channels/planGenerationStatus/messages/PlanGenerationStatusMessage'

components:
  messages:
    PlanGenerationStatusMessage:
      name: PlanGenerationStatusMessage
      contentType: application/json
      payload:
        $ref: '#/components/schemas/PlanGenerationStatusPayload'

  schemas:
    PlanGenerationStatusPayload:
      type: object
      required:
        - eventType
        - generationId
        - userId
        - status
        - timestamp
      properties:
        eventType:
          type: string
          enum:
            - plan.generation.queued
            - plan.generation.processing
            - plan.generation.completed
            - plan.generation.failed
        generationId:
          type: string
          format: uuid
        userId:
          type: string
          format: uuid
        status:
          type: string
          enum:
            - queued
            - processing
            - completed
            - failed
        progress:
          type: integer
          minimum: 0
          maximum: 100
          nullable: true
        planId:
          type: string
          format: uuid
          nullable: true
        errorCode:
          type: string
          nullable: true
        message:
          type: string
          nullable: true
        timestamp:
          type: string
          format: date-time
```
