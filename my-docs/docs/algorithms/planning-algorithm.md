# Алгоритм формирования недельного плана

## Назначение

Алгоритм формирует недельный план студента на основе учебных задач, дедлайнов, трудоёмкости, календарных событий и приоритетов. Результатом является набор задач, распределённых по дням и временным слотам.

## Входные данные

| Данные | Источник |
|---|---|
| Список задач | `GET /tasks` |
| Дедлайны из LMS | LMS API |
| События календаря | `GET /calendar/events` |
| Оценка трудоёмкости | поле `estimated_minutes` |
| Приоритет | DMN-модуль или пользовательский ввод |

## Основные шаги

1. Получить задачи пользователя.
2. Получить дедлайны из LMS, если интеграция подключена.
3. Получить календарные события пользователя.
4. Объединить задачи и события в единый набор ограничений.
5. Для каждой задачи определить приоритет через DMN-модуль.
6. Отсортировать задачи по дедлайну, приоритету и трудоёмкости.
7. Построить доступные временные слоты по дням недели.
8. Распределить задачи по слотам.
9. Проверить перегруз по дням.
10. При перегрузе пересобрать план или сформировать рекомендации.
11. Вернуть черновик недельного плана пользователю.
12. После подтверждения сохранить план.

## Псевдокод

```text
function generateWeeklyPlan(userId, week):
    tasks = loadTasks(userId)
    deadlines = loadLmsDeadlines(userId)
    events = loadCalendarEvents(userId, week)

    normalizedTasks = mergeTasksAndDeadlines(tasks, deadlines)

    for task in normalizedTasks:
        task.priority = dmnPriority(task.urgency, task.effort, task.hasDeadline)

    sortedTasks = sortByPriorityDeadlineAndEffort(normalizedTasks)
    slots = buildFreeSlots(week, events)

    plan = emptyPlan(week)

    for task in sortedTasks:
        slot = findBestSlot(task, slots)
        if slot exists:
            placeTask(plan, task, slot)
        else:
            addRecommendation(plan, task, "Недостаточно свободного времени")

    if hasOverload(plan):
        plan = rebalance(plan)

    return plan
```

## Правила приоритизации

Приоритет определяется через DMN. Высокая срочность всегда даёт высокий приоритет. Средняя срочность при большой трудоёмкости и фиксированном дедлайне повышается до высокого приоритета. Низкая срочность без дедлайна остаётся низкой.

## Проверка перегруза

Перегруз возникает, если суммарное плановое время задач на день превышает доступное время с учётом календарных событий. При перегрузе система может перенести часть задач, предложить ручную корректировку или показать риск просрочки.
