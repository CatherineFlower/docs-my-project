# REST API

REST API построен вокруг ресурсов авторизации, пользователей, задач, календарных событий и планов. Спецификация оформлена в формате OpenAPI 3.0.3.

Интерактивная Redoc-версия доступна на странице: [/api/rest](/api/rest).

Исходный OpenAPI-файл: [`/static/api/openapi.yaml`](/api/openapi.yaml)

## Подход к проектированию

API соответствует второму уровню зрелости Ричардсона: используются ресурсы, HTTP-методы и явные URI. Для идентификации пользователя применяется JWT Bearer token.

## Основные ресурсы

| Группа | URI | Назначение |
|---|---|---|
| Auth | `/auth/login`, `/auth/register`, `/auth/logout` | Авторизация, регистрация и выход |
| Users | `/users/me`, `/users/profile` | Данные пользователя и настройки |
| Tasks | `/tasks` | Получение списка задач |
| Calendar | `/calendar/events` | Получение календарных событий |
| Plans | `/plans/generate`, `/plans/weekly` | Генерация, получение и сохранение недельного плана |

## Основные модели

`User` описывает пользователя системы. `Task` описывает учебную задачу. `Event` описывает событие календаря. `Plan` описывает недельный план. `PlanDay` и `PlannedTask` описывают вложенную структуру плана для отображения на UI.

## Замечание по асинхронной генерации

В OpenAPI генерация плана может быть описана как `POST /plans/generate`. В синхронной версии endpoint возвращает готовый план. В асинхронной версии endpoint должен возвращать `202 Accepted` и `generationId`, а дальнейший статус передаваться через WebSocket, описанный в AsyncAPI.
