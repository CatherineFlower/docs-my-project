# Хранение данных

## Характер данных

| Сущность | Характер данных | Технология |
| --- | --- | --- |
| Пользователь | Структурированные транзакционные данные | Реляционная БД |
| Настройки | Структурированные транзакционные данные | Реляционная БД |
| Задача | Структурированные транзакционные данные | Реляционная БД |
| Событие календаря | Структурированные транзакционные данные | Реляционная БД |
| План | Структурированные транзакционные данные | Реляционная БД |
| Запланированная задача | Структурированные транзакционные данные | Реляционная БД |
| Логи активности | Полуструктурированные аналитические данные | Аналитическое хранилище |

## Обоснование выбора

Основные сущности системы имеют строгую структуру, связаны внешними ключами и требуют транзакционной консистентности. Поэтому для них выбрана реляционная база данных.

Логи активности быстро растут, записываются часто и используются в аналитических сценариях. Поэтому они логически отделены от основной бизнес-модели.

## OLTP-контур

К OLTP относятся `users`, `user_settings`, `tasks`, `calendar_events`, `plans`, `planned_tasks`. Эти таблицы участвуют в пользовательских сценариях и должны сохранять целостность данных.

## Аналитический контур

К аналитическому контуру относится `activity_logs`. Данные логов можно агрегировать и использовать для оценки поведения пользователей, выявления перегрузок и анализа качества планирования.
