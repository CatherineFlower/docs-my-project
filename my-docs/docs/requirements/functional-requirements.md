# Функциональные требования

## UC-01. Регистрация

**Актор:** студент.  
**Предусловие:** пользователь не авторизован.

Основной поток:

1. Пользователь открывает экран регистрации.
2. Вводит email, пароль и подтверждение пароля.
3. Система валидирует данные.
4. Система создаёт аккаунт.
5. Пользователь попадает в приложение.

**Постусловие:** аккаунт создан.

## UC-02. Авторизация

**Актор:** студент.  
**Предусловие:** аккаунт уже создан.

Основной поток:

1. Пользователь открывает экран входа.
2. Вводит email и пароль.
3. Система проверяет учётные данные.
4. Система возвращает токен доступа.
5. Пользователь переходит на главный экран.

## UC-03. Создание задачи

**Актор:** студент.  
**Предусловие:** пользователь авторизован.

Основной поток:

1. Пользователь нажимает «Добавить задачу».
2. Вводит название, предмет, дедлайн, трудоёмкость и описание.
3. Система сохраняет задачу.
4. Задача появляется в списке.

## UC-04. Генерация недельного плана

**Актор:** студент.  
**Предусловие:** у пользователя есть задачи и/или календарные события.

Основной поток:

1. Пользователь открывает экран генерации плана.
2. Выбирает задачи и события.
3. Нажимает «Сгенерировать».
4. Система получает задачи, дедлайны и календарные события.
5. Система определяет приоритеты задач.
6. Система распределяет задачи по дням.
7. Система проверяет перегрузку.
8. Пользователь видит сформированный план.

## UC-05. Ручная корректировка плана

Пользователь открывает режим редактирования, переносит задачи между днями, меняет порядок задач и сохраняет изменения.

## UC-06. Сохранение плана

Пользователь подтверждает план, после чего система сохраняет его как актуальный недельный план.
