# Нефункциональные требования

## NFR-01. Производительность

Время отклика для 95% пользовательских запросов должно быть не более 1 секунды. Требование относится к основным операциям: получение задач, профиля, календарных событий и текущего плана.

## NFR-02. Доступность

Система должна обеспечивать доступность не ниже 99%. Это важно, поскольку пользователь может обращаться к плану в течение учебного дня.

## NFR-03. Безопасность

Передача данных должна выполняться по TLS 1.2 или выше. Для авторизации используется Bearer JWT. Система должна учитывать требования законодательства о персональных данных.

## NFR-04. Масштабируемость

Архитектура должна поддерживать рост до 50 000 одновременных пользовательских сессий. Для MVP это целевой ориентир, а не стартовая нагрузка.

## NFR-05. Надёжность

Данные пользователей должны регулярно резервироваться. Для основных сущностей требуется транзакционная консистентность.

## NFR-06. Поддерживаемость

Документация ведётся в формате Docs as Code. Все изменения проходят через Git, Markdown-файлы хранятся вместе с проектом, сборка выполняется через Docusaurus.

## Непокрытые категории

Локализация ограничена русским языком, так как MVP ориентирован на запуск в РФ. Портируемость ограничена веб-версией. Совместимость с LMS вынесена за пределы MVP, но архитектурно предусмотрена для следующих версий.
