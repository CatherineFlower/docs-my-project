# Стейкхолдеры и RACI

## Матрица RACI для функции генерации недельного плана

| Задача / активность | Команда разработки | Владелец продукта | Студент | Администратор системы |
|---|---|---|---|---|
| Разработка алгоритма приоритизации | R | A | C | I |
| Проектирование интерфейса плана | R | A | C | I |
| Настройка правил хранения данных | R | I | I | A |
| Финальная приёмка и запуск функции | I | A | C | R |

R — реализует, A — утверждает, C — консультируется, I — информируется.

## Описание ролей

Команда разработки отвечает за реализацию алгоритма, API, интерфейса и модели данных. Владелец продукта принимает решения по бизнес-логике и отвечает за соответствие функции целям продукта. Студент участвует как источник пользовательских требований и тестирует удобство сценариев. Администратор системы отвечает за стабильность, эксплуатацию, мониторинг и сопровождение.

## Вопросы для интервью

### Студенты

1. Как вы сейчас понимаете, что задачу нужно делать именно сегодня?
2. Что вы делаете, если в один день выпадает несколько дедлайнов?
3. Насколько важно иметь возможность вручную передвинуть задачу, предложенную системой?
4. Как часто вы хотели бы получать напоминания о плане на день?

### Владелец продукта

1. Должна ли система предлагать платные функции уже на этапе MVP?
2. Какой процент отклонения студента от плана считается допустимым?
3. Нужно ли закладывать интеграции с внешними календарями во второй версии?

### Команда разработки

1. Какие ограничения есть у базы данных по количеству одновременных запросов на расчёт плана?
2. Нужно ли хранить историю всех сгенерированных планов или только текущий план?
3. Что должна делать система, если внешний сервис уведомлений недоступен?

## Event Storming

Для процесса создания плана выделяются события: задача создана, дедлайн импортирован, событие календаря получено, приоритет рассчитан, перегруз обнаружен, план сформирован, план отредактирован, план сохранён.
