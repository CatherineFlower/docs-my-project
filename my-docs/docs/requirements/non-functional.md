# Нефункциональные требования

| ID | Категория | Требование | Приоритет | Обоснование |
|---|---|---|---|---|
| NFR-01 | Производительность | Время отклика не более 1 секунды для 95% обычных запросов | Must Have | Медленный интерфейс снижает удержание пользователей |
| NFR-02 | Доступность | SLA не ниже 99% | Must Have | Сервис должен быть доступен в периоды высокой учебной нагрузки |
| NFR-03 | Безопасность | Использование TLS 1.2+ и защита персональных данных | Must Have | Система хранит пользовательские данные и учебные задачи |
| NFR-04 | Масштабируемость | Поддержка до 50 000 одновременных пользователей | Should Have | Требуется для масштабирования на несколько вузов |
| NFR-05 | Надёжность | Ежедневное резервное копирование | Should Have | Потеря планов и задач критична для пользователя |
| NFR-06 | Сопровождаемость | Документация хранится в репозитории и обновляется через pull request | Should Have | Соответствует подходу Docs as Code |
| NFR-07 | Наблюдаемость | Основные действия пишутся в activity logs | Should Have | Нужно для диагностики и аналитики поведения |

## Безопасность

Система должна хранить пароли только в виде хеша, не передавать токены в URL, использовать HTTPS и ограничивать доступ к данным пользователя по user_id. Для авторизации используется JWT Bearer token.

## Производительность генерации плана

Обычные REST-запросы должны выполняться синхронно. Генерация недельного плана может выполняться асинхронно, так как она объединяет задачи, события календаря, импортированные дедлайны и алгоритм приоритизации. Статус генерации передаётся клиенту через WebSocket.

## Непокрытые категории MVP

Локализация не входит в MVP, так как первый запуск ориентирован на русскоязычную аудиторию. Портируемость ограничена веб-версией. Полная совместимость с LMS вынесена за рамки MVP и рассматривается для следующих версий.
