# Функциональные требования MVP

## UC-01. Регистрация

**Актор:** студент.  
**Предусловия:** отсутствуют.  
**Цель:** создать аккаунт пользователя.

Основной поток: пользователь вводит email и пароль, система валидирует данные, после успешной проверки создаёт аккаунт.

**Постусловие:** аккаунт создан, пользователь может перейти к авторизации или сразу попасть в систему в зависимости от реализации клиентского приложения.

## UC-02. Авторизация

**Актор:** студент.  
**Предусловия:** аккаунт существует.  
**Цель:** получить доступ к личным задачам и планам.

Основной поток: пользователь вводит email и пароль, система проверяет учётные данные, выдаёт access token и возвращает данные пользователя.

**Постусловие:** пользователь авторизован.

## UC-03. Создание задачи

**Актор:** студент.  
**Предусловия:** пользователь авторизован.  
**Цель:** добавить учебную задачу в систему.

Основной поток: пользователь нажимает «Добавить задачу», вводит название, предмет, дедлайн, оценочное время выполнения и описание, после чего сохраняет задачу.

**Постусловие:** задача сохранена и доступна в списке задач.

## UC-04. Просмотр задач

**Актор:** студент.  
**Предусловия:** пользователь авторизован.  
**Цель:** увидеть список текущих учебных задач.

Основной поток: пользователь открывает экран задач, система загружает список задач, отображает статусы, приоритеты и дедлайны.

**Постусловие:** пользователь видит актуальный список задач.

## UC-05. Генерация недельного плана

**Актор:** студент.  
**Предусловия:** существуют задачи или календарные события.  
**Цель:** сформировать недельный план на основе дедлайнов, трудоёмкости и доступного времени.

Основной поток: пользователь нажимает «Сформировать план», система получает задачи, события календаря и дедлайны из LMS, определяет приоритеты, проверяет перегруз по дням и формирует план.

**Постусловие:** недельный план сформирован и доступен для просмотра.

## UC-06. Ручная корректировка плана

**Актор:** студент.  
**Предусловия:** недельный план сформирован.  
**Цель:** изменить результат автоматического планирования.

Основной поток: пользователь открывает режим редактирования, переносит задачи между днями, меняет время выполнения, удаляет или добавляет задачи в план.

**Постусловие:** изменения применены локально и могут быть сохранены.

## UC-07. Сохранение плана

**Актор:** студент.  
**Предусловия:** недельный план сформирован или отредактирован.  
**Цель:** зафиксировать план в системе.

Основной поток: пользователь нажимает «Сохранить», система валидирует структуру плана, сохраняет дни, задачи и порядок отображения.

**Постусловие:** план сохранён в базе данных.

## UC-08. Получение событий календаря

**Актор:** календарь студента.  
**Предусловия:** пользователь подключил календарь или события созданы внутри системы.  
**Цель:** учесть занятость пользователя при планировании.

Основной поток: система получает события за период недели и использует их как ограничения при распределении задач.

**Постусловие:** события учтены при генерации плана.

## UC-09. Импорт дедлайнов из LMS

**Актор:** LMS вуза.  
**Предусловия:** пользователь подключил LMS.  
**Цель:** автоматически получить учебные задания и дедлайны.

Основной поток: система получает задания из LMS, преобразует их в задачи и использует при формировании плана.

**Постусловие:** импортированные дедлайны доступны в системе.
