# Стейкхолдеры

## Внутренние стейкхолдеры

| Стейкхолдер | Роль в проекте |
| --- | --- |
| Студент | Основной пользователь системы. Создаёт задачи, формирует план, корректирует результат. |
| Владелец продукта | Определяет стратегию, бизнес-ценность, приоритеты развития и границы MVP. |
| Команда разработки | Реализует веб-приложение, API, алгоритм планирования и интеграции. |
| Администратор системы | Сопровождает инфраструктуру, контролирует доступность и стабильность. |

## Внешние стейкхолдеры

| Стейкхолдер | Влияние |
| --- | --- |
| Регуляторы персональных данных | Определяют требования к хранению и обработке данных пользователей. |
| LMS вуза | Может выступать источником учебных задач и дедлайнов. |
| Календарь студента | Источник событий, влияющих на доступное время. |
| Платёжные провайдеры | Понадобятся при запуске подписки. |
| Магазины приложений | Актуальны при развитии мобильной версии. |

## RACI для функции генерации плана

| Активность | Команда разработки | Владелец продукта | Студент | Администратор |
| --- | --- | --- | --- | --- |
| Разработка алгоритма приоритизации | R | A | C | I |
| Проектирование интерфейса плана | R | A | C | I |
| Настройка хранения данных | R | I | I | A |
| Финальная приемка и запуск | I | A | C | R |

R — реализует, A — утверждает, C — консультируется, I — информируется.
